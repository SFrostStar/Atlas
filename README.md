## О проекте

Atlas — независимая доработка Horizon: клиент Minecraft на Rust с собственным оформлением, новыми функциями и удобным управлением сборками. Проект поддерживается и развивается.

## Скачать и играть

[**Скачать Atlas для Windows x64**](https://github.com/SFrostStar/Atlas/releases/latest)

1. В разделе Assets скачайте и запустите `Atlas-Launcher.exe`. Если релиз предлагает ZIP, распакуйте его и запустите `Atlas Launcher.exe`.
2. Создайте локальный профиль и нажмите «Играть».
3. Подтвердите скачивание файлов игры. При первом запуске нужен интернет;
   Java и ресурсы установятся автоматически. Готовые файлы Minecraft в ZIP не включены.

Миры и настройки сохраняются в папке `data` рядом с лаунчером. При обновлении сохраняйте её.
Это ранняя версия: возможны игровые ошибки. Microsoft-вход пока не настроен;
серверы, требующие Microsoft-авторизацию, недоступны с локальным профилем.

## Возможности

- **Свой лаунчер.** Отдельные сборки, папки сохранений, журнал запуска и управление несколькими окнами игры.
- **Персонализация.** Русский и английский языки, светлая и тёмная темы, акцентные цвета и оформление главной.
- **Графика и меню.** Возможности движка Horizon, собственные меню Atlas и экран загрузки с логотипом и ночным пейзажем.
- **Ресурспаки.** Ускоренная подготовка ресурсов на Windows и загрузка в фоне с прогрессом.
- **Память сборки.** Настраиваемый лимит памяти нативного игрового процесса.
- **Профили.** Локальные аккаунты и подготовленный Microsoft-вход, для которого нужен собственный Client ID и доступ к Minecraft API.
- **Discord Rich Presence.** Название Atlas, логотип и текущая версия в Discord.

Совместимость и производительность зависят от компьютера, сервера и ресурсов. Это развивающийся неофициальный клиент.

## Запуск и разработка

Для разработки интерфейса нужны Node.js и npm:

```sh
npm ci
npm start
```

Проверки лаунчера:

```sh
npm test
```

Подготовка игровых ресурсов и сборка Rust описаны в [руководстве движка](engine/atlas/README.md). Ресурсы Minecraft берутся из собственной законно полученной копии игры и в репозиторий не входят. Клонирование исходников само по себе не устанавливает готовую игру, локальные инструменты или подготовленные ресурсы.

Для сборки игры под Windows: `powershell -ExecutionPolicy Bypass -File scripts/Build-Atlas.ps1`.

Версия Atlas задаётся в `package.json`. Команда `npm version <версия> --no-git-tag-version` обновляет и поле версии, и сгенерированный `package-lock.json`. Затем пересоберите клиент и лаунчер для этой версии. Сайт и ссылка на скачивание берут последний опубликованный релиз с GitHub.
Потребуются Rust, C++ toolchain и подготовленные ресурсы; готовую игру устанавливайте из Releases.
Локальная рабочая документация в `docs/` не публикуется.

## Приватность

В репозитории хранятся исходники и оформление проекта. `.gitignore` исключает:

- Миры, резервные копии и данные игровых сборок.
- Аккаунты, токены, файлы авторизации и локальные настройки.
- Логи, отчёты о сбоях, скриншоты и управляющие сокеты.
- Кэши, ресурсы Minecraft, скачанные инструменты и собранные приложения.

Перед отправкой проверяется список файлов:

```sh
python scripts/check_repository_privacy.py
```

## Обновления

Скачайте и откройте `Atlas-Launcher.exe`. При первом запуске он установит лаунчер в `%LOCALAPPDATA%\Atlas` и создаст ярлык на рабочем столе. При запуске с ярлыка Atlas проверяет наличие обновления и сразу открывает лаунчер, если версия актуальна или GitHub недоступен. Миры, аккаунты, настройки и игровые ресурсы хранятся рядом с папкой версий.

Для перехода с portable-версии 1.2.0 положите новый `Atlas-Launcher.exe` рядом со старым `Atlas Launcher.exe` и запускайте новый файл. Он установит актуальную версию в подпапку `versions` той же установки и продолжит использовать её `data` и `runtime`. Внутреннее обновление 1.2.0 требует прежнего формата релиза, поэтому переход на загрузчик выполняется один раз вручную.

Для сборки нового формата из готового portable-комплекта используйте `node scripts/build-release.cjs <папка-portable> <новая-папка-результата> --bootstrap`. Пакет выдаёт два комплекта файлов.

- Сначала опубликуйте `payload/` как prerelease `atlas-payload-<версия>`. Там один ZIP и его манифест.
- Затем опубликуйте `stable/Atlas-Launcher.exe` в стабильном релизе `atlas-<версия>`. Этот EXE скачивает сайт. [Как GitHub выбирает стабильный релиз](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)

У старых portable-релизов с ZIP обновления по-прежнему устанавливаются при закрытии лаунчера. Для перехода с 0.1 или 1.0.0 обновите portable-комплект вручную, сохранив папку `data`.

Коммиты, отправка изменений, теги и публикация релизов выполняются только по явной команде SFrostStar.
