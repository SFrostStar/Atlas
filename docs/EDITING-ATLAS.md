# Как менять сам Minecraft в Atlas

Исходники игры находятся в `engine/atlas`. Основа — Horizon с GitHub: тег **v0.2.93**, коммит `b6c936f82b08798057161bdfa577e3aac53fb91e`. Создана локальная ветка `atlas/local`. Установленная игра Horizon не менялась.

В Atlas изменены подпись в левом нижнем углу титульного экрана на **Atlas 26.3**, заголовок игрового окна на **Atlas**, заголовки дополнительных настроек на **Atlas Settings**, **Atlas Extras** и **Atlas Graphics**, значок и сообщения клиента. Собранный клиент расположен в `runtime/atlas-client.exe`, инструмент управления — `runtime/atlas-ctl.exe`.

Собственные Rust-пакеты и файлы настроек используют имена `atlas-*`. Скрипт сборки создаёт `atlas-client.exe` и `atlas-ctl.exe`. MIT LICENSE и THIRD_PARTY_NOTICES.md сохранены вместе с именами исходных авторов; сторонняя папка `third_party/wgpu-hal` остаётся необходимой частью сборки.

Atlas — отдельное приложение-лаунчер. Файлы интерфейса Atlas не управляют устройством главного меню игры. Для изменения меню или логики игры редактируй Rust в `engine/atlas`, собери клиент и выбери полученный EXE в настройках Atlas.

## Что уже можно включать и выключать

У каждой сборки собственная папка в `data/instances`. В ней игра читает `atlas-extras.txt`. Эти ключи не требуют пересборки:

```text
fullbright:false
dynamicLights:false
autoReconnect:false
mouseTweaks:false
mouseTweaksWheel:false
sort:false
```

`true` включает, `false` выключает. `dynamicLights` — свет от факелов и других источников в руках и на земле; `mouseTweaks` — управление переносом предметов; `sort` — кнопки сортировки инвентаря. Меняй их при закрытой игре: иначе игра при выходе может записать свои текущие настройки поверх файла. При ручном редактировании сохраняй остальные строки файла.

Для этой версии не используй старые ключи `minimap`, `fps` и `zoom` как обычные переключатели: эти функции перенесены в официальные WASM-моды. Старые поля сохранены в коде для миграции.

## Где менять главное меню и настройки

Пути ниже указаны относительно `engine/atlas`:

| Что менять | Файл и ориентир |
| --- | --- |
| Кнопки главного меню, их подписи и доступность | `crates/atlas-client/src/title.rs`, `fn buttons`, ветка `Mode::Main` |
| Действия кнопок главного меню | Тот же файл, `fn click`, ветки `(Mode::Main, Some(...))` |
| Окно настроек и расположение пунктов | `crates/atlas-client/src/options_ui.rs`, `Page::Main`, `Page::Atlas`, `Page::Extras` |
| Список и логика дополнительных переключателей | `crates/atlas-client/src/extras.rs`, `Extras`, `Item`, `rows`, `Item::switch`, `Item::cycle` |
| Сохранение дополнительных настроек | Тот же файл: `Extras::parse`, `Extras::serialize`, `Extras::save` |
| Применение настроек в игре | `crates/atlas-client/src/game/extras.rs`, `game/options.rs`, `game/startup_menu.rs` |
| Графические настройки | `crates/atlas-client/src/graphics.rs`, `graphics_ui.rs` |
| Общая карта устройства движка | `AGENTS.md`, `docs/architecture.md` |

### Пример: деактивировать кнопку Multiplayer

В `title.rs`, внутри `Mode::Main`, найди кнопку:

```rust
&lang::get_or("menu.multiplayer", "Multiplayer"),
true,
4,
```

Поменяй только `true` на `false`. После сборки кнопка останется видимой, но будет недоступна. Это пример изменения собственного клиента, а не настройка готового EXE. Чтобы скрыть кнопку совсем, убери соответствующий вызов `b(...)` и проверь клавиатурную навигацию и размещение остальных кнопок.

### Пример: добавить свой переключатель

Удобный образец — уже работающий `Fullbright` в `extras.rs`:

1. Добавь поле `pub my_feature: bool` в `Extras` и `my_feature: false` в `Default`.
2. Добавь чтение ключа `myFeature` в `Extras::parse` и запись в `serialize`.
3. Добавь вариант `MyFeature` в `Item`, строку `Ok(MyFeature)` в `rows()` и обработку во всех соответствующих `match` методах `Item`.
4. В коде нужной функции проверь `self.settings.extras.my_feature`. Один интерфейсный переключатель без такой проверки не меняет поведение игры.
5. Добавь проверку сохранения/загрузки рядом с существующими тестами `extras.rs`, собери клиент и проверь в отдельном тестовом мире.

После этого переключатель появится на странице Extras внутри игровых настроек. Для отдельной кнопки прямо на титульном экране также нужно действие в `title.rs` и обработчик в `game/startup_menu.rs`. Не перенумеровывай существующие ID кнопок без проверки обработчиков.

## Сборка своего клиента на Windows

В папке проекта уже подготовлены переносимые Rust **1.99.1** и LLVM-MinGW **23.1.4**. Они расположены в `tools/cargo`, `tools/rustup` и `tools/llvm-mingw-20261020-ucrt-x86_64`. Системный PATH не изменялся, установка Visual Studio для этого варианта сборки не требуется. Используется официально поддерживаемая Rust цель `x86_64-pc-windows-gnullvm` с UCRT.

Открой терминал в папке Atlas и запусти:

```powershell
.\scripts\Build-Atlas.ps1
```

Или дважды нажми `Build Atlas.cmd` в корне проекта. Скрипт только собирает исходники и не запускает игру. Быстрая проверка компиляции:

```powershell
.\scripts\Build-Atlas.ps1 -CheckOnly
```

Эквивалентная команда из `engine/atlas`:

```powershell
cargo build --locked --profile fast -p atlas-client --bin atlas-client --bin atlas-ctl --features mods
```

Скрипт сам задаёт локальные пути инструментов на время сборки. Результат копируется в `runtime/atlas-client.exe` и `runtime/atlas-ctl.exe`, рядом кладутся нужные DLL. Закрой игру перед пересборкой и перезапусти лаунчер после неё. Включена поддержка WASM-модов, аудио и контроллеров, как у исходной версии. Лаунчер использует локальные подготовленные ресурсы Minecraft 26.3 из `runtime/.local/atlas-client/26.3` и отдельную папку выбранной сборки. При переходе на другую базовую версию ресурсы нужно подготовить заново.

Обычный запуск клиента требует `--resources` с абсолютным путём к подготовленным ресурсам, рабочей папки сборки и переменной `ATLAS_HOME` с той же папкой. В этой сборке ресурсы находятся в `runtime/.local/atlas-client/26.3`.

Файлы ресурсов, миры, учётные данные и `.local/` не нужно добавлять в Git. Исходный MIT LICENSE находится в `engine/atlas/LICENSE`; его следует сохранять вместе с копиями исходников.

## Управление игрой

В игре включи Agent Control и скопируй данные подключения. По умолчанию Atlas использует `%TEMP%/atlas-control.json`. Состояние можно проверить так:

```powershell
.\runtime\atlas-ctl.exe --socket "$env:TEMP\atlas-control.json" state
```

Для MCP: команда — полный путь к `runtime/atlas-ctl.exe`, аргументы — `--socket`, полный путь к `atlas-control.json`, `mcp`. Это локальное соединение с игрой; изменение исходников всё равно требует пересборки.

Discord Rich Presence настраивается в лаунчере и использует общий ID Atlas из `package.json` → `atlasDiscord`; игрокам не нужно регистрировать своё приложение. Microsoft-вход настраивается отдельно: `docs/ACCOUNTS.md`.

WASM-моды для переименованного API `atlas:mods` нужно собирать с текущим `atlas-mod-sdk`. Совместимость готовых модулей другого API не предполагается.
